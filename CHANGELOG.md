## 0.5.0 — 2026-10-28

### Added

- **Bounded redacted worker diagnostic frames with explicit job correlation** (`createWorkerDiagnosticReporter`, `createWorkerDiagnosticReceiver`, `WorkerDiagnosticFrame`, `WorkerDiagnosticRecord`, `WorkerDiagnosticLimits`)
  Opt-in reporter and receiver enforce message and byte budgets, reject stale or duplicate frames, preserve callback failure accounting and integrate with existing host persistence without creating workers, listeners or transport queues. Received checkpoints do not guarantee final crash reports.

## 0.4.0 — 2026-10-26

### Added

- **Track diagnostic assertion outcomes separately from process exit evidence through @absolutejs/diagnostics/run** (`createDiagnosticRunLifecycle`, `DiagnosticRunStatus`, `DiagnosticRunSnapshot`)
  A host-neutral lifecycle preserves failed and source-invalidated results, records explicit exit codes/signals, and marks successful assertions interrupted if the process subsequently fails. It installs no listeners or storage and returns immutable bounded snapshots.

## 0.3.0 — 2026-10-22

### Breaking

- **Requires Elysia 2.0.0-rc.0** (`diagnosticCorrelationPlugin`, `diagnosticsPlugin`)
  Elysia 2.0.0-rc.0 renamed every lifecycle hook to its `on` form and removed setup/cleanup (now onStart/onStop). This package now builds and tests against Elysia 2.0.0-rc.0 and requires `elysia ^2.0.0-rc.0`, which also accepts later release candidates and 2.0.0. Its plugin's hooks are renamed to match.
  _Migration:_ Upgrade `elysia` and every `@elysia/*` package to 2.0.0-rc.0 or later, then rename lifecycle hooks in your own server: request → onRequest, beforeHandle → onBeforeHandle, afterHandle → onAfterHandle, afterResponse → onAfterResponse, error → onError, parse → onParse, transform → onTransform; setup/cleanup → onStart/onStop. absolutejs/scripts codemods/elysia-rc-hooks.ts does the renames (run it before upgrading Elysia).
